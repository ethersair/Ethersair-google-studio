۱. خلاصه اجرایی و نقشه راه کلی

تصویر کلی پروژه EthersAir و مسیر پیشرو

EthersAir یک پلتفرم دیفای چندزنجیره‌ای (Multi-chain DeFi) است که هدفش ارائه توکن، استیکینگ، سواپ، و در نهایت بریج بین چندین بلاکچین است. رویکرد فعلی: شروع با زیرساخت EVM (که پایدارترین و کمدردسرترین محیط برای توسعه است)، تکمیل Solana، و سپس اتصال زنجیره‌ها به هم با LayerZero.

فرانت‌اند Swap

یک فایل تک‌صفحه‌ای (ethersair-swap.html) با ethers.js v6 ساخته شده که موارد زیر را پشتیبانی می‌کند:

  • اتصال به MetaMask و تشخیص/سوییچ خودکار شبکه Base Sepolia
  • دو تب برای دو استخر (ETHERSAIR⇄WETHERSAIR و ETHERSAIR⇄mWBTC)
  • محاسبه خودکار مقدار خروجی تخمینی از طریق getAmountOut
  • Approve خودکار و اجرای swapExactTokensFor
  • نمایش موجودی زنده و وضعیت reserve های استخر
نکته اجرا: این فایل باید از طریق یک سرور محلی (نه file://) باز شود، چون MetaMask روی فایل‌های محلی به‌طور پیش‌فرض غیرفعال است. یک سرور Node.js ساده (بدون وابستگی خارجی) برای این کار نوشته شده:
const http = require("http");
const fs = require("fs");
const path = require("path");
const PORT = 3000;

http.createServer((req, res) => {
  let filePath = req.url === "/" ? "/ethersair-swap.html" : req.url;
  filePath = path.join(__dirname, filePath);
  fs.readFile(filePath, (err, data) => {
    if (err) { res.writeHead(404); res.end("Not found"); return; }
    const ext = path.extname(filePath);
    const contentType = ext === ".html" ? "text/html" : "text/plain";
    res.writeHead(200, { "Content-Type": contentType });
    res.end(data);
  });
}).listen(PORT, () => console.log(`Server running at http://localhost:${PORT}`));

اجرا با: node server.js سپس باز کردن http://localhost:3000 در همان پروفایل کروم که MetaMask روی آن نصب است.

۵. راهاندازی کامل محیط WSL2/Ubuntu برای توسعه Solana

۵.۱ نصب WSL2 (نه WSL1!)

هشدار حیاتی: اگر wsl -l -v نسخه 1 نشان دهد، باینری‌های لینوکسی ازجمله Node.js با خطای Exec format error شکست می‌خورند. حتماً قبل از هر کاری این را بررسی کنید.
# در CMD (Administrator):
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
wsl --set-version Ubuntu 2
wsl -l -v   # باید VERSION = 2 نشان دهد

اگر wsl --install به‌دلیل مسدودی aka.ms با timeout مواجه شد، نصب دستی:

msiexec /i wsl_update_x64.msi
curl -L -o ubuntu-rootfs.tar.gz https://cloud-images.ubuntu.com/wsl/releases/22.04/current/ubuntu-jammy-wsl-amd64-wsl.rootfs.tar.gz
wsl --import Ubuntu C:\WSL\Ubuntu .\ubuntu-rootfs.tar.gz

۵.۲ رفع مشکل DNS در WSL

ISP در برخی موارد DNS را hijack می‌کند. رفع دائمی:

# /etc/wsl.conf باید شامل این بخش باشد:
[network]
generateResolvConf = false

# سپس دستی بنویسید:
sudo bash -c 'echo "nameserver 1.1.1.1" > /etc/resolv.conf'
sudo bash -c 'echo "nameserver 8.8.8.8" >> /etc/resolv.conf'

بعد از تغییر wsl.conf، لازم است از CMD ویندوز اجرا شود: wsl --shutdown و سپس دوباره wsl -d Ubuntu.

۶. مشکلات شبکه و راهحل‌های دائمی

پروکسی Psiphon — نکته حیاتی

IP محلی پروکسی Psiphon با هر بار قطع/وصل شدن تغییر می‌کند. همیشه قبل از هر عملیات شبکه‌ای در WSL:

  1. در برنامه Psiphon، به تب Logs بروید
  2. آخرین (پایین‌ترین) خط با الگوی HTTP proxy is running on 192.168.x.x port 8080 را پیدا کنید (آدرس‌های 169.254.x.x را نادیده بگیرید)
  3. در WSL export کنید:
export http_proxy="http://IP_فعلی:8080"
export https_proxy="http://IP_فعلی:8080"
export HTTP_PROXY="http://IP_فعلی:8080"
export HTTPS_PROXY="http://IP_فعلی:8080"

پروکسی برای npm (ویندوز، خارج از WSL)

npm config set proxy http://IP_فعلی:8080
npm config set https-proxy http://IP_فعلی:8080

پروکسی برای apt

sudo bash -c 'cat > /etc/apt/apt.conf.d/95proxy << EOF
Acquire::http::Proxy "http://IP_فعلی:8080";
Acquire::https::Proxy "http://IP_فعلی:8080";
EOF'
